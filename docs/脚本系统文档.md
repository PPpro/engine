# 脚本系统文档

一个引擎真正意义上的脚本系统，应该只设计并服务于实现项目侧业务逻辑用的，他使用的语言可以是 ts，可以是 lua，可以是蓝图，甚至可以类似 godot 一样的自研语言 GDScript。
脚本系统 和 ts 脚本 是两个概念，但是由于我们引擎使用 ts 脚本实现的，所以 ts 脚本 和 脚本系统 相关的工作常常被混淆在一起。  
所以这篇文档说是 脚本系统，其实更确切的应该是涵盖了整个 ts 脚本体系的相关工作流说明。  

这一块主要会分为两点：
- 构建工具
- 运行时模块系统

## 构建工具

由于历史原因，构建工具被实现为多套，分散在仓库各地，主要涉及以下几个仓库：
- 项目构建
    - creator-programming: https://github.com/cocos/creator-programming, 这是一个服务于项目侧脚本构建的基础库，该仓库被实现为一个 monorepo，意味着这个完整的库是由多个子库构成的，这样的好处是能够尽量复用子库代码，子库包括： 
        - creator-programming-babel-preset-cc: 这是一个 babel preset，里边是一些预设给 cocos 使用的 babel 插件集，类比 babel preset env
        - creator-programming-common: 一些通用的工具库
        - creator-programming-import-maps: 支持 import-map 的模块解析 （import-map 是一个前端的模块映射标准，参考 https://developer.mozilla.org/en-US/docs/Web/HTML/Element/script/type/importmap）
        - creator-programming-mod-lo: 核心模块 module loader，这里涉及到脚本编译的模块解析，脚本编译，这里就包括了对 npm 模块的支持相关逻辑
        - creator-programming-rollup-plugin-mod-lo: 将 creator-programming-mod-lo 封装为 rollup 插件，给其他 rollup 构建工具使用
        - creator-programming-quick-pack: 主要提供 build 接口，驱动 mod-lo 编译
        - creator-programming-test-utils：私有模块，不对外发布，用于本地做 unit test 的一些测试工具
    - programming 编辑器扩展插件：https://github.com/cocos/cocos-editor/tree/develop/app/builtin/programming，这块是编辑器处理开发时项目脚本编译的模块，他核心实现是通过 asset-db-interop 来监听 db 的消息，由 db 的消息来发起编译请求，通知 packer-driver 来处理可能并发的编译请求
    - build-script 项目脚本发布时构建：https://github.com/cocos/cocos-editor/blob/develop/app/builtin/builder/source/worker/builder/asset-handler/script/build-script.ts
- 引擎构建
    - quick-compiler: https://github.com/cocos/cocos-editor/tree/develop/packages/quick-compiler, 这是引擎的开发时的构建工具，满足构建时快速构建的需求，核心的思路是他的构建输出是散文件，可以充分利用这些散文件的 mtime 来做增量编译，这里区别于 vite 的按需编译，增量编译更适合 cocos 的需求。
    - 重点介绍一下 ccbuild https://github.com/cocos/cocos-ccbuild，这个库目前是只支持了引擎构建，但是他的定位是 cocos creator 完整的构建解决方案，包括项目构建和引擎构建。只不过现阶段还只是处理引擎的发布时的构建需求。未来他需要覆盖的包括：引擎的开发时、发布时构建，项目侧的开发时、发布时构建，引擎的 dts 构建，具体模块包括：
        - build-engine 引擎的构建工具，目前包括 2 个后端 js-engine, ts-engine(给 OH 平台 AOT 使用)，未来需要合并 quick-compiler
        - dts-bundler 构建 cc.d.ts
        - modularize 引擎模块信息的查询，给引擎模块化使用，引擎模块化相关的设计参考 [文档](TODO)
        - stats-query 引擎整体信息查询
        - bundler 汇集所有可能的打包工具后端，目前包括 roller，未来可以加入 esbuild，webpack，turbopack 等，编辑器都统一使用该模块导出的接口，避免重复安装打包工具，相关 issue: TODO
        - transformer 汇集所有可能的编译工具后端，目前包括 babel，typescript，未来可以加入 swc，编辑器都统一使用该模块导出的接口，避免重复安装编译工具，相关 issue: TODO
