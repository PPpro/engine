# 脚本系统文档

一个引擎真正意义上的脚本系统，应该只设计并服务于实现项目侧业务逻辑用的，他使用的语言可以是 ts，可以是 lua，甚至也可以是蓝图。  
脚本系统 和 ts 脚本 是两个概念，但是由于我们引擎使用 ts 脚本实现的，所以 ts 脚本 和 脚本系统 常常被混淆在一起。  
所以这篇文档说是 脚本系统，其实更确切的应该是涵盖了整个 ts 脚本体系的相关工作流说明。  
这一块主要会分为两点：
- 构建工具
- 运行时模块系统

## 构建工具

由于历史原因，构建工具被实现为多套，分散在仓库各地，主要涉及以下几个仓库：
- 项目构建
    - creator-programming: https://github.com/cocos/creator-programming, 这是一个服务于项目侧脚本构建的基础库，该仓库被实现为一个 monorepo，意味着这个完整的库是由多个子库构成的，这样的好处是能够尽量复用子库代码 
        - creator-programming-babel-preset-cc: 这是一个 babel preset，里边是一些预设给 cocos 使用的 babel 插件集，类比 babel preset env
        - creator-programming-common: 一些通用的工具库
        - creator-programming-import-maps: 支持 import-map 的模块解析 （import-map 是一个前端的模块映射标准，https://developer.mozilla.org/en-US/docs/Web/HTML/Element/script/type/importmap）
        - creator-programming-mod-lo: 核心模块，这里涉及到脚本编译的模块解析，脚本编译，这里就包括了对 npm 模块的支持
        - creator-programming-rollup-plugin-mod-lo: 将 creator-programming-mod-lo 封装为 rollup 插件，给其他 rollup 构建工具使用
        - creator-programming-quick-pack: 主要提供 build 接口，驱动 mod-lo 编译
        - creator-programming-test-utils：私有模块，不对外发布，用于本地做 unit test 的一些测试工具
    - programming 编辑器扩展插件：https://github.com/cocos/cocos-editor/tree/develop/app/builtin/programming
- 引擎构建
    - quick-compiler, 这是引擎的开发时构建工具，满足构建时快速构建的需求，核心的思路是他的构建输出是散文件，可以充分利用这些散文件来做 mtime 的缓存管理
    - ccbuild https://github.com/cocos/cocos-ccbuild
