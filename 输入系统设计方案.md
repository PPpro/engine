# Unity 架构：
- ActionAsset
    - ActionMap： ActionScheme to Action
        - Action 抹平输入设备的差异
        - Action Binding 将 Action 绑定到不同输入设备 / 不同输入按键
            - Modifier 与 Unreal 的 Modifier 是不同的概念，Unity 的 Modifier 是用于组合键的需求，例如 shift+1
            - interaction 对标 Unreal 的 trigger
            - Processor 类似 Unreal 的 Modifier，区别是 Unreal 的是预处理，Processor 是后处理

- Player Input 组件
    - ActionAsset
    - Behavior: SendMessage, BroadcastMessage, UnityEvent, C# Event
    - Camera：用于 PlayerInputManager 的 split screen 能力
    - UI Input Module

- Player Input Manager
    - join
    - split screen

- 状态查询支持
    - InputAction.readValue
    - Gamepad.current.leftStick.readValue

- UI 支持课题
    - Pointer Type, Navigation Type, Tracking Type
    - UI vs game Input 歧义问题
        - PointerType 歧义
        - Navigation 歧义
    - Pointer Behavior：
        - Single Mouse or Pen But Multi Touch And Track 多设备输入，后者覆盖前者
        - Single Unified Pointer，多点输入，后者覆盖前者
        - All Pointers As Is，所有输入，都以后者为准

- 测试框架

# Unreal 方案
- Input Action
- Action Mapping Context 输入映射上下文，用于区分不同场景下使用的映射表，比如行走状态，与驾驶状态，是两个不同的输入映射上下文，这样子可以避免输入冲突，也不会浪费 CPU 周期
- Modifier：Input Modifiers are pre-processors that alter the raw input values that UE4 receives before sending them on to Input Triggers.The Enhanced Input Plugin ships with a variety of Input Modifiers to perform tasks like changing the order of axes, implementing "dead zones", converting axial input to world space, and several others.
- Trigger: Input Triggers determine whether or not a user input, after passing through an optional list of Input Modifiers, should activate the corresponding Input Action within its Input Mapping Context

# 方案差异
- Unity 是将 Action 映射到一个 KeyCode Array，抹平了输入设备的差异
- Cocos 是将 Event 分类，再细分 Event 阶段，更拘泥于底层细节，不是一个很好的产品设计


# 一些想法 / 需求
- Action 的优势，是可以做 ReBinding （BindingIconList 要不要提供？）
- 支持 Gamepad Cursor
- 在屏虚拟按钮，可以作为一个典型的 CustomInput 的案例
- 每个层级都能够支持自定义，CustomDevice，CustomBindingComposite
- 支持 inputRecord, 用于自动化，或者视频回放
- Unity 的 UI 是一定会接收事件的，开发者可以通过 EventSystem.current.isPointerOverGameObject 来判断要不要处理 game input（这点跟 cocos 目前的设计有差异，cocos UI 是直接吞噬事件）
